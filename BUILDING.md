# Taskbar Hero Clone — Build and Test

A minimal Electron + PixiJS taskbar idle RPG with an Android WebView build.

## Current build outputs

- **Android debug APK** — generated by the `Build Android APK` workflow; suitable for local testing and sideloading.
- **Android unsigned release APK** — generated separately; it must be signed with your release key before public distribution.
- **Windows NSIS installer** — generated by the `Build and test Taskbar Hero` workflow and uploaded as a workflow artifact.

Workflow artifacts are downloadable from the run's **Artifacts** section:
- [Build Android APK runs](https://github.com/ArkansasIo/taskbar-hero/actions/workflows/android.yml)
- [Build and test runs](https://github.com/ArkansasIo/taskbar-hero/actions/workflows/ci.yml)

The repository does not commit compiled APK/EXE files. Build artifacts expire according to each workflow's retention setting.

## Build Android locally

Requirements: Node.js 20+, JDK 17, Android SDK API 35, and Gradle 8.10.2.

```bash
npm ci
npm run android:assets
cd android
gradle --no-daemon :app:assembleDebug
gradle --no-daemon :app:assembleRelease
```

Outputs:
- `android/app/build/outputs/apk/debug/app-debug.apk`
- `android/app/build/outputs/apk/release/app-release-unsigned.apk`

## Build desktop locally

```bash
npm ci
npm start
```

On Windows, create the installer with:

```bash
npm run dist
```

The installer is created under `dist/`. The CI workflow uploads it as an artifact; it should not need a personal access token just to package and upload the executable as a workflow artifact.

## Saving and security notes

- Android saves live in WebView origin-scoped local storage. Clearing app data removes local progress.
- Keep release signing keys and passwords out of source control. Configure signing credentials through protected GitHub Actions secrets when signing a release.
- The unsigned Android release APK is not a signed production distribution package.
